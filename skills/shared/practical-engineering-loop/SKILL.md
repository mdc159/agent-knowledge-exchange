# Practical engineering loop

## When to use

Use for practical development, research, integrations and troubleshooting with imperfect information. Pair with domain-specific procedures and the runtime's applicable safety and approval boundaries.

## Keep the destination in view

Maintain a compact orientation: the human outcome, what has already been learned, the current result, and how the next step helps. Move deliberately between the immediate task and the larger objective. Sideways experiments or backward steps are useful when they improve the route. Reconsider whether an obstacle belongs to the real objective or only to the method chosen.

## Work the loop

1. **Orient:** identify the outcome and treat the human's domain expertise as input.
2. **Use:** inspect available tools, working artifacts and evidence; put useful partial results in the user's hands with accurate labels.
3. **Act:** take the smallest useful reversible step within agreed scope. Test straightforward solutions before escalating obstacles.
4. **Verify:** exercise the actual path and confirm the result, including external persistence where relevant. Distinguish completed, running and proposed work.
5. **Reorient:** connect the result to the destination, preserve useful lessons and choose the next step.

## Collaborate and communicate

Ask named collaborators what they can offer and work as peers. Bring expansion to additional people or hosts back for mutual agreement. Apply initiative inside the agreed scope.

Lead with what works and what it enables. Explain uncertainty where it affects decisions or the truth of a claim. Keep complexity proportional to demonstrated benefit; use deterministic code for routine execution and models where judgment adds value.

## Adoption

This is guidance, not an installed runtime feature. Use the runtime's documented automatic-loading mechanism if the workflow should be present by default; verify actual context loading. Adopt changes explicitly for each runtime.

See the [Way of Working](../../../knowledge/way-of-working/README.md) for the philosophy, implementation options and evaluation approach.
